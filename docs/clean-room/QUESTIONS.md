| 1 | 2026-09-22 | C1 | §8.4 `merge` when the entry holds several values and the first is a container: which values take part? Oracle (main document `append`, then `.include(duplicate="merge") "f"`): `a { x = 1 }⏎a { y = 2 }` with f = `a { z = 3 }` → `a: ⟨{x: int 1, z: int 3} \| {y: int 2}⟩`; with f = `a = 5` → `a: ⟨int 5 \| {y: int 2}⟩`. So only the first value takes part and the others are kept. Nested values keep their own priorities: `.priority 2⏎a { x = 1 }⏎.include(duplicate="merge", priority=5) "f"` with f = `a { x = 9 }` → `a: {x: int 9 @5} @2`. Implemented as observed; please confirm and add cases. | |
| 2 | 2026-09-22 | C1 | Does the §8.3 rule "an inherited value is always replaced by a later explicit value" apply only under `append`? Oracle, `strategy:merge`: `d { a = 1 }⏎e { .inherit "d"; a = 2 }` → `e.a: ⟨int 1 \| int 2⟩`; `d { a { x = 1 } }⏎e { .inherit "d"; a { y = 2 } }` → `e.a: {x: int 1, y: int 2}`. `strategy:error`: `d { a = 1 }⏎e { .inherit "d"; a = 2 }` → **error**. A value that a merge went into, or that the §8.4 scalar quirk replaced, is still inherited: `d { a { x = 1 } }⏎e { .inherit "d"; .include(duplicate="merge") "f"; a = 7 }` with f = `a = 5` → `e.a: int 7`; with f = `a { y = 2 }` and `a { z = 3 }` in place of `a = 7` → `e.a: {z: int 3}`. Implemented as observed. | |
| 3 | 2026-09-22 | C1 | §8.5 `no-implicit-arrays` with priorities: §8.5 gives priority-0 examples only. Oracle, `no-implicit-arrays`: `a = 1⏎.priority 3⏎a = 2⏎.priority 1⏎a = 3⏎.priority 3⏎a = 4` → `a: [int 2 @3, int 4 @3]`, the array itself without a priority (0). So priorities are compared first (§8.3), and the collection array has priority 0 whatever its elements have. Consequence: `.priority 3⏎a = 1⏎a = 2⏎a = 3` → `a: int 3 @3`, not the `[1, 2, 3]` that "later repeats are appended" suggests. Likewise `.priority 3⏎a = 1⏎a = 2⏎.priority 1⏎a = 3` → `a: int 3 @1`, and `a = 1⏎a = 2⏎.priority 2⏎a = 3` → `a: int 3 @2`. An inherited value is replaced, not collected: `d { a = 1 }⏎e { .inherit "d"; a = 2 }` → `e.a: int 2`. Implemented as observed (element priorities are not kept, see the C1 log entry). | |
| 4 | 2026-09-22 | C1 | `merge` together with `no-implicit-arrays`. Oracle, both set: `a = 1⏎a = 2⏎a = 3` → `a: int 3` (the collection array counts as an array, so the §8.4 scalar quirk replaces it); `b = 1⏎b = 2⏎b = [3]` → `b: [int 1, int 2, int 3]`. With `no-implicit-arrays` only: `b = 1⏎b = 2⏎.include(duplicate="merge") "f"⏎b = 6` with f = `b = 5` → **error** (libucl reports "cannot allocate memory for an array"). Implemented as observed, the last as a `DuplicateKeyError`. Should the project match that error, or is it a divergence to decide? | |
