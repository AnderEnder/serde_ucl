| 1 | 2026-09-22 | C1 | §8.4 `merge` when the entry holds several values and the first is a container: which values take part? Oracle (main document `append`, then `.include(duplicate="merge") "f"`): `a { x = 1 }⏎a { y = 2 }` with f = `a { z = 3 }` → `a: ⟨{x: int 1, z: int 3} \| {y: int 2}⟩`; with f = `a = 5` → `a: ⟨int 5 \| {y: int 2}⟩`. So only the first value takes part and the others are kept. Nested values keep their own priorities: `.priority 2⏎a { x = 1 }⏎.include(duplicate="merge", priority=5) "f"` with f = `a { x = 9 }` → `a: {x: int 9 @5} @2`. Implemented as observed; please confirm and add cases. || spec-v2: §8.4 (merge uses the first value only; nested entries compared by priority) |
| 2 | 2026-09-22 | C1 | Does the §8.3 rule "an inherited value is always replaced by a later explicit value" apply only under `append`? Oracle, `strategy:merge`: `d { a = 1 }⏎e { .inherit "d"; a = 2 }` → `e.a: ⟨int 1 \| int 2⟩`; `d { a { x = 1 } }⏎e { .inherit "d"; a { y = 2 } }` → `e.a: {x: int 1, y: int 2}`. `strategy:error`: `d { a = 1 }⏎e { .inherit "d"; a = 2 }` → **error**. A value that a merge went into, or that the §8.4 scalar quirk replaced, is still inherited: `d { a { x = 1 } }⏎e { .inherit "d"; .include(duplicate="merge") "f"; a = 7 }` with f = `a = 5` → `e.a: int 7`; with f = `a { y = 2 }` and `a { z = 3 }` in place of `a = 7` → `e.a: {z: int 3}`. Implemented as observed. || spec-v2: §8.3 (inherited rule is `append`-only; table for merge/rewrite/error; stays inherited after merge) |
| 3 | 2026-09-22 | C1 | §8.5 `no-implicit-arrays` with priorities: §8.5 gives priority-0 examples only. Oracle, `no-implicit-arrays`: `a = 1⏎.priority 3⏎a = 2⏎.priority 1⏎a = 3⏎.priority 3⏎a = 4` → `a: [int 2 @3, int 4 @3]`, the array itself without a priority (0). So priorities are compared first (§8.3), and the collection array has priority 0 whatever its elements have. Consequence: `.priority 3⏎a = 1⏎a = 2⏎a = 3` → `a: int 3 @3`, not the `[1, 2, 3]` that "later repeats are appended" suggests. Likewise `.priority 3⏎a = 1⏎a = 2⏎.priority 1⏎a = 3` → `a: int 3 @1`, and `a = 1⏎a = 2⏎.priority 2⏎a = 3` → `a: int 3 @2`. An inherited value is replaced, not collected: `d { a = 1 }⏎e { .inherit "d"; a = 2 }` → `e.a: int 2`. Implemented as observed (element priorities are not kept, see the C1 log entry). || spec-v2: §8.5 (collected array has priority 0: quirk; §8.7 element priorities unobservable) |

| 7 | 2026-09-23 | C2 | §3.4: where the line lookahead starts, and quoted first keys.
