# Stage A native release reference gate (spec team)

This spec-owned tool tests the released `spec-v22` Stage A interface: ten clean
public-interface cases and exactly 43 symbols. Implementation participants may
run this as a black box; they must not read this directory or upstream source.
The broad unreleased research proposal is not an input or acceptance requirement.

The release gate builds the reference at the commit recorded in the released
inventory, with URL/signature/Lua support disabled, in ignored `target/c15-oracle`.
It verifies the exact checkout and public-header digest. An oracle-only run writes
actual-host snapshots into an external directory. A separate non-writing run then
checks each candidate against reference and those snapshots, including four
header/library combinations, C11/C++11, all 43 signatures/links and ten cases.
Existing released target snapshots must match the newly generated reference.
Expected outputs are never copied from Darwin to Linux or generated by a candidate.

Public black-box CLI (from repository root):

```sh
python3 tools/capi-conformance/ci.py \
  --candidate-include PREFIX/include \
  --candidate-library PREFIX/lib/libucl.a \
  --candidate-library PREFIX/lib/libucl.so \
  --golden-dir target/c15-oracle/golden
```

Use `libucl.dylib` for Darwin. Candidate libraries are repeatable arguments.
`--golden-dir` directly contains the ten `.txt` cases and, only after successful
comparison, `reference-evidence.json` with reference/contract/probe/candidate
hashes and native platform. This evidence can be archived with release checks.
Inputs require Git, CMake, native C/C++ compilers, Python and a writable ignored
build directory. Native supported release jobs are Linux amd64/arm64 and Darwin
arm64; no successful Linux execution is implied by this tool's presence alone.

Spec-side local reuse: `--oracle-source PATH` accepts an existing clean checkout
only at the pinned commit. This path is forbidden implementation input. The
underlying `run.py --golden-dir PATH` can compare prebuilt reference libraries;
`--update-golden` is strictly oracle-only and rejects a candidate argument.

No source files from the upstream checkout enter SDK/source archives. Only clean
public cases, generated snapshots and observable validation evidence are passed
across the clean-room boundary. The released contract and header are unchanged.
